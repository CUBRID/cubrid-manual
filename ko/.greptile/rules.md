# CUBRID 한국어 매뉴얼 리뷰 기준 (`ko`)

저장소 공통 기준은 `../.greptile/rules.md`, 정본은 `../docs/STYLE_GUIDE.ko.md`입니다.
이 파일은 한국어 매뉴얼에만 추가로 적용되는 기준입니다.
공통 규칙과 이 규칙은 **덮어쓰지 않고 합쳐집니다.**

---

## 1. 기준 문체 — `~한다`체

| 종결 | 건수 |
|:---|:---:|
| `한다.` | 6,093 |
| `된다.` | 1,979 |
| `있다.` | 1,905 |
| **평서체 합계** | **9,977** |
| `합니다.` | 423 |
| `입니다.` | 304 |
| `됩니다.` | 35 |
| **경어체 합계** | **762** |

새로 추가·수정하는 문장은 평서체로 씁니다.

```rst
로캘을 설정한 후 데이터베이스를 생성해야 한다.      (O)
로캘을 설정한 후 데이터베이스를 생성해야 합니다.    (X)
```

### 예외

- 표·그림 캡션
- 목록 항목의 명사형 종결
- 오류 메시지 원문 인용
- 릴리스 노트의 공지 문장

---

## 2. 오류 메시지 원문은 수정하지 않습니다

`admin/error_log*.rst`와 본문에 인용된 오류 메시지는 **제품이 실제로 출력하는 문자열**입니다.

```rst
-- 유지: 제품 출력 원문
ERROR: Column 'a' cannot be null.

-- 수정: 이를 설명하는 서술 문장
해당 컬럼이 NULL을 허용하지 않을 때 발생한다.   → 해당 칼럼이 ...
```

메시지를 바꾸면 사용자가 실제 로그와 문서를 대조할 수 없습니다.
**판정이 애매하면 메시지 원문으로 간주해 유지합니다.**

## 3. 디렉터리별 제외 대상

| 디렉터리 | 유지해야 하는 것 |
|:---|:---|
| `sql/` | SQL 문법 정의(BNF, `<...>`, `[...]`), 예약어, 데이터 타입명, 함수명, 콜레이션 이름, 시스템 카탈로그 식별자, 예제 데이터 |
| `admin/` | `cubrid.conf` 계열 파라미터명과 값, `cubrid` 유틸리티 명령·옵션, 환경 변수, `statdump` 지표명, 로그 출력 예시 |
| `api/` | 클래스명, 인터페이스명, 메서드명, 함수명, 상수명, 프로퍼티명, 접속 URL, 반환 타입 |
| `pl/` | Java SP 시그니처, PL/CSQL 예제 코드, 시스템 패키지·프로시저 이름 |
| `release_note/` | 이슈 번호(CBRD-xxxxx, APIS-xxxx), 변경 이력 원문, 이슈 제목 인용 |

### `메소드`·`리턴` 판정

API 매뉴얼에서 가장 오탐이 많은 지점입니다.

```rst
getConnection() 메소드는 연결을 리턴한다.
  → getConnection() 메서드는 연결을 반환한다.        (서술 문장 → 수정)

**Return Value**
  → 원문 유지                                       (API 절 제목 → 유지)

CUBRIDStatement.getMethod()
  → 원문 유지                                       (코드 식별자 → 유지)
```

## 4. SQL 문법 정의와 설명의 정합성

표기 문제와 **별개로** 다음은 반드시 지적합니다.

- 문법 정의에 없는 절이 파라미터 설명에 등장
- 파라미터 설명에 있는 절이 문법 정의에서 누락
- 옵션 설명의 기본값과 `admin/config.rst`의 기본값이 다름
- `.. versionadded::` 버전과 본문 "x.x 버전부터" 서술이 어긋남

---

## 5. 번역 용어 일관성

한 문서 안에서 같은 영문 개념을 서로 다른 한글 용어로 부르면 지적합니다.

```rst
질의를 실행한다. ... 이 쿼리는 ...      → 하나로 통일
```

표기 표준의 용어(질의, 부질의, 파라미터, 칼럼, 반환)를 우선하고,
처음 등장할 때만 영문을 괄호로 병기합니다. 이미 병기된 용어에 반복 병기를 요구하지 않습니다.

---

## 6. 위험 절차 경고

백업/복구, `deletedb`, 볼륨 조작, HA 전환, 스키마 변경 절차에는
사전 조건과 되돌릴 수 없는 동작에 대한 경고가 있어야 합니다.

경고 없이 명령어만 제시되면 `.. warning::` 추가를 제안합니다.
`완벽한`, `손실 없이`, `100%`, `절대` 같은 보증성 표현은 반드시 지적합니다.
